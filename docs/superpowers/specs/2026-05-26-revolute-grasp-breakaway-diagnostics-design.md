# Revolute Grasp Breakaway Diagnostics Design

## Goal

Diagnose and fix the visible post-grasp reverse or retreat motion when operating revolute joints, using assets 45219, 45622, and 45693 as the first validation set.

The desired behavior is one continuous manipulation:

1. Move the gripper to the handle.
2. Close on the handle.
3. Rotate the articulated object in one continuous operation.

The recorded video must start from the initialized static robot state, before the arm begins moving toward the handle.

## Current Findings

The selected outputs under `manipulation/output/table_revolute_selected_45219_45622_45693` show these three assets already run through the joint-aware path:

- `control_profile` is `joint_aware_run_arti_open`.
- `legacy_demo_executed` is `false`.
- `joint_aware_attempt_count` is `1`.
- `status` is `success`.
- `settle_steps` is `0`.

This means the visible retreat is not caused by running the legacy open demo twice or by candidate retry. The likely source is the post-grasp revolute target sequence in `manipulation/run.py`.

The current revolute sequence is built by `_compute_revolute_grasp_hold_arc_targets()`:

- hold at the grasp pose,
- move along a short tangential breakaway,
- then switch to arc targets computed from the original handle center.

That switch can create a discontinuity: the breakaway endpoint and the first arc point are generated by different local rules, so the arm can visibly reverse before continuing the same rotation.

## Design

### Revolute Target Generation

Rewrite the revolute breakaway generator so the post-grasp trajectory is continuous:

- Keep a short hold phase after gripper close to stabilize contact.
- Generate breakaway as the first small segment of the same circular motion used by the arc.
- Make the arc start from the breakaway endpoint's continuation angle, not from the original zero-angle handle pose.
- Preserve the existing `direction_sign` behavior for trying positive and negative revolute directions.
- Keep the grasp offset along `approach_dir` so the end effector remains at the intended contact side of the handle.

The trajectory must satisfy these invariants:

- The first non-hold target is close to the grasp pose.
- The transition from breakaway to arc has no large positional jump.
- Angular progress around the revolute axis is monotonic for the chosen `direction_sign`.
- Adjacent target distances are bounded by the expected small per-step motion.

### Structured Feedback

Add structured diagnostics to `result.json` so failures can be detected without relying only on video inspection.

Record stage feedback for:

- after pre-grasp,
- after grasp pose,
- after gripper close,
- selected pull steps,
- final state.

Each stage should include:

- target position,
- observed end-effector position,
- tracking error,
- target DOF value and delta when available,
- gripper-on-handle metrics when meaningful.

Record revolute target diagnostics:

- grasp target,
- hold target count,
- breakaway target count,
- arc target count,
- first pull target,
- final pull target,
- maximum adjacent target distance,
- breakaway-to-arc transition distance,
- first non-hold distance from grasp,
- angular monotonicity flag,
- signed angular progress summary.

The existing `pull_step_gripper_metrics` stays, but it should be complemented by target-sequence diagnostics because the current metrics report contact after execution, not whether target generation itself caused the retreat.

### Video Capture

Change video capture so each saved video begins with the initialized static robot:

- Clear stale video frames before recording the joint-aware attempt.
- Immediately record an initial static segment after closed DOF reset and observation refresh, before pre-grasp motion.
- Use a small fixed initial count, such as 30 frames at the current output FPS.
- Record metadata in `result.json`: `video_capture_start_stage`, `initial_static_frame_count`, and whether the initial frames were preserved.

The joint-aware path must not clear those initial frames after they are recorded.

### Validation

Add focused helper tests before changing behavior:

- `_compute_revolute_grasp_hold_arc_targets()` produces a continuous sequence.
- The breakaway-to-arc transition distance is bounded.
- Revolute angular progress is monotonic for both positive and negative `direction_sign`.
- The first non-hold target is near the grasp pose.

Run the existing helper tests after implementation:

```bash
pytest tests/test_run_helpers.py
```

Then run the three validation assets with the existing selected part ids:

```bash
cd manipulation
python run.py --mode run_arti_open --headless --save_video --joint_type revolute --part_id 5 --object_path /Titan/dataset/data_gapartnet/partnet_mobility_StorageFurniture_Table/revolute_joint/45219 --task_root output/table_revolute_selected_45219_45622_45693
python run.py --mode run_arti_open --headless --save_video --joint_type revolute --part_id 4 --object_path /Titan/dataset/data_gapartnet/partnet_mobility_StorageFurniture_Table/revolute_joint/45622 --task_root output/table_revolute_selected_45219_45622_45693
python run.py --mode run_arti_open --headless --save_video --joint_type revolute --part_id 2 --object_path /Titan/dataset/data_gapartnet/partnet_mobility_StorageFurniture_Table/revolute_joint/45693 --task_root output/table_revolute_selected_45219_45622_45693
```

Validation passes when:

- all three runs still return `status=success`,
- `legacy_demo_executed=false`,
- `joint_aware_attempt_count=1` unless a genuine contact failure requires retry,
- `settle_steps=0` on success,
- `breakaway_to_arc_transition_distance` is within the configured bound,
- `arc_angle_monotonic=true`,
- the video metadata reports the initial static frames,
- visual inspection shows no post-grasp reverse or retreat before rotation continues.

## Scope

In scope:

- `manipulation/run.py` revolute target generation.
- `manipulation/run.py` result diagnostics.
- `manipulation/run.py` video capture start point for `run_arti_open`.
- `tests/test_run_helpers.py` helper coverage.

Out of scope:

- Replacing contact-based manipulation with direct DOF control.
- Reworking cuRobo or IK control.
- Changing prismatic behavior except where shared diagnostics are harmless.
- Broad batch selection or dataset summarization refactors.

## Risks

The main risk is changing target generation enough to reduce contact force on some revolute handles. The mitigation is to keep the existing hold phase, preserve grasp offset, and validate on the named assets before broad batch runs.

Another risk is increasing video duration or memory use. The initial static segment should be short and fixed, and MP4 writing already uses the in-memory `video_frames` list in the current path.
